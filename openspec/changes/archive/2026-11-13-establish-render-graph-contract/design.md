# Design

## Context

见 [proposal.md](proposal.md#why)。当前 [Runtime](../../../../Runtime/Main.cpp) 先取得宿主目标、准备视口和 UI，再以同一即时列表上传、清屏和绘制。[UI 录制](../../../../Editor/ImGui/UiRenderer.cpp) 内部写入投影、顶点及索引缓冲；[字体 atlas 更新](../../../../Editor/ImGui/UiTextures.cpp) 通过写入区域暂存纹理再拷贝到目标矩形。宿主交付的 [PresentColor](../../../../Platform/Presentation.hpp) 具有已约定的进出状态，但每次取得仍要初始化本轮颜色。它们是本次设计的直接样本，产品接线留到 T04。

## Goals / Non-Goals

**Goals:**

- 让一个独立 CPU 消费者通过正式 Graph 入口表达上述帧，取得足够精确的声明记录，供 T02 建立依赖、T03 检查实际用途。
- 让图局部身份、内容效果、外部 RHI 状态和 Pass 权限各有唯一来源，错误能定位到实际 Pass 或资源。

**Non-Goals:**

- 本包不实现图编译、拓扑、裁剪、分配计划或物化，不切换 RHI 同步模式，不接入产品帧或改变现有窗口、UI 和上传确认行为。
- 不引入第二套 RHI 描述、通用 Blackboard、隐式资源复制、多队列、持久图或资源池。持续预算、跨帧池和更广的原生能力按既定工作包推进。

## Decisions

### 1. 资源身份和范围分开保存

在 `Engine/Renderer/RenderGraph` 新增声明模块及独立 `PhysaraRenderGraph` 构建目标，只依赖 `PhysaraCore` 和 `PhysaraRHI`。Graph 持有资源、版本、Pass 与导出记录，构造时从统一来源分配不复用的非零图代。可沿用 [Core 身份及代推进](../../../../Engine/Core/Identity.hpp)，给不同资源类别独立的类型标签并附加逻辑版本。不得用帧槽号、对象地址或名称充当图代。调试名称可重复，只用于定位。声明和查询先核对图代、类型及索引/版本，再访问表项。

存储描述复用公共 RHI 的 Texture/Buffer 描述；纹理使用规范化的 mip、layer、aspect 组合，缓冲使用半开字节区间。全范围是显式简写，显式长度零、越界和溢出均失败。图以合法起点的剩余容量检查长度，aspect 由有效格式的 color/depth/stencil 语义校验。现有 [RHI Resolve](../../../../RHI/Common/Misc.cpp) 取交集，不能作为图入口校验；设备支持、样本兼容性和物理创建另由 T02/T03 负责。

导入持有公共 RHI 强引用；在现有产品路径中，以同一 RHI 对象作为身份键，不取后端对象名。等价的规范范围、入口状态、结束状态与初始内容声明归并到原导入版本；不等价则拒绝。需要不同访问范围时从同一导入身份分别声明用途。首版要求导入方提供规范的 RHI 对象；当前 GL 不支持从同一原生对象另外创建 Texture/Buffer wrapper。将来若引入这种入口，应先在导入边界明确物理身份归并。导出记录指定版本、范围和外部用途，供后续编译和执行消费；宿主取得凭据不入图。

导入前按公共 RHI 位域校验 `entry` 和 `final`，拒绝 `Unknown` 与未定义的状态位，并指出具体字段。后续编译和执行再检查当前设备支持的用途。 [公共 tracker](../../../../RHI/Common/StateTracking.cpp#L60)

### 2. 用单链写版本保存内容事实

每个资源从创建或导入版本开始，写声明从当前写版本向前推进。旧版读取仍是显式引用；同一存储何时覆盖、读旧内容能否排在覆盖前，由 T02 决定。以每次写的生产者、前一版本、用途和规范范围保存增量，比复制整份子资源状态或自动复制 GPU 资源更简单。版本链本身不应让不相交的访问形成数据依赖。

用途记录把读写性质和内容效果分开。Load 与保留式局部更新都记录对旧范围的内容依赖；Clear 和明确完整覆盖定义写范围；Discard 或 StoreDontCare 不能成为有效内容的来源。区域字体更新在图内按涉及的 mip 声明保留，区域外的内容来自前一有效版本；T01 不建立逐 texel 有效性表。导入 `ShaderResource` 仅表达用途状态，不会把未写的窗口颜色或诊断候选变成有效输入。

Read、Load 和 Export 从请求版本向初始版本回溯。每条有效写入只扣除它覆盖的部分。仍待确认的范围若遇到丢弃或未写的初始内容，声明失败。范围按 mip、layer、aspect 或字节区间切分，避免逐子资源展开。T02 使用同一批记录处理物理覆盖顺序、跨范围依赖和非法反馈。

首发配置的 `Clear` 需要标记为 `isRenderTarget` 的纹理和匹配的清除值，`CopyDestination` 的传输清除也遵循这一前提。普通复制目标可以用完整覆盖声明上传，也可以在已有内容上用 `Load` 声明区域更新。 [OpenGL 清除入口](../../../../RHI/OpenGL/CommandListTransfer.cpp#L85)

### 3. 让图持有 Pass 数据，资源只能按声明解析

`AddPass` 的 setup 同步运行，可以借用调用栈完成声明。首版 execute 使用无捕获的类型化入口，延迟数据通过拥有型 `PassData` 提交。图在成功构建后保存其稳定地址和销毁操作；不接受把栈引用、即将覆写的像素指针或未持有的 span 作为延迟数据。需要延迟的字节由拥有型载荷或寿命明确的帧存储提供。使用无捕获入口是为了减少引用逃逸，而不是假设 C++ 能自动识别载荷内的一切借用。

复用 [Core::FrameArena](../../../../Engine/Core/FrameArena.hpp) 作为 Pass 存储：由图调用方提供独立于 UI 几何区的有界 arena，并在首次分配前预留。对象由图析构，在调用方回收字节前结束借用。当前 UI 会在发布首个地址前预留几何及上传预算；因此不在这段已借出的 arena 上晚扩容。T01 的 CPU 消费者提供该存储；T04 接线时由帧槽提供可复用的存储，重用仍遵守帧槽完成合同。setup 或存储失败不提交部分 Pass，未发布对象正常销毁；构图失败可整体放弃，不提供同一失败图的恢复流程。

`PassResources` 以当前 Pass 的用途表授权，验证资源、精确版本、访问用途及包含关系后才交给解析器。首版要求一条同用途声明覆盖所请求范围，不用若干分离声明拼出更宽的视图。T01 用 CPU 解析器观察授权及拒绝；T03 将合法请求解析为实际资源或绑定 recipe。Pass 数据携带逻辑身份与必要值；图管理的纹理、缓冲不从捕获的裸句柄或全局服务绕过声明。权限检查和物化失败各自报告原因。

## Risks / Trade-offs

- **误把状态或相邻写入当作内容初始化** → 保留导入内容事实和每次写范围；用未写 mip、区域更新及 StoreDontCare 检查是否错误扩张有效内容。
- **错误导入或 Pass 越权导致隐藏依赖** → 导入只产生一个底层资源身份；Release 中在调用解析器前拒绝错误图代、版本、用途和范围。诊断包含发生阶段、可用的 Pass/资源名和原因，名称不参与查找。
- **构图失败留下写版本或悬空载荷** → 写版本和回调随 Pass 成功一并发布；用局部数据离开作用域及构建失败的拥有型对象检查清理。仅凭图成功声明不推断 GPU 工作或完成。

## Migration Plan

T01 加入正式声明模块，产品继续使用 D04 的既有路径。下游按开发计划逐包消费同一份声明，不需复制一个独立产品入口。

| 后续包 | 消费 T01 的内容与接线边界 |
|---|---|
| [D05-T02](../../../../Docs/Developments/D03-D05-FramePipeline.md#d05-t02) | 用版本、范围、内容依赖和输出记录构造 RAW/WAR/WAW。活性依赖和存储顺序约束分别表达；输出确定顺序和物理计划，非法图明确失败。 |
| [D05-T03](../../../../Docs/Developments/D03-D05-FramePipeline.md#d05-t03) | 按首次使用物化资源和绑定，从 Pass 权限解析实际句柄，将用途送给同一 RHI tracker。清除的传输用途先于 Draw；只读深度附件并采样需按 [§7.5](../../../../Docs/Architecture.md#barriers) 验证实际 GL 访问与像素，不能只检查状态位。Compute/image/SSBO 的多消费域同步留在 [D08-T04](../../../../Docs/Developments/D08-D11-RenderPaths.md#d08-t04)。 |
| [D05-T04](../../../../Docs/Developments/D03-D05-FramePipeline.md#d05-t04) | 把诊断图、字体/区域、VB/IB 和投影上传，与 UI 采样、颜色附件及导出拆成可见依赖。稳定 UiTextureId 只映射到本帧的版本；PresentColor 仍由宿主取得，UI 和 View 仍按接受回执确认。替换 Runtime 原顺序编排。 |
| [D05-T05](../../../../Docs/Developments/D03-D05-FramePipeline.md#d05-t05) | 仅在主图尚未执行时建独立 UI-only 图，重新导入有效旧输出。执行中途失败取消呈现，已经发出的命令仍按现有提交或受控退出保活；失败不推进历史。 |
