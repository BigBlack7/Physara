# Design

## Context

D10-T03 的 `ViewWork` 按 View 请求冻结相机、工作集和不透明策略，`ForwardRenderer::PlanView` 与 `FinishView` 用帧前预算准备实际角色，`View::Publish` 根据请求及图回执确认输出。当前发布入口要求颜色路径等于最新请求，因此另一条路径准备中时，原有效策略无法作为新帧继续发布。 [View 准备](../../../../Engine/Renderer/Prepare/ViewPreparation.cpp) · [帧入口](../../../../Runtime/Frame.cpp) · [View 确认](../../../../Engine/Renderer/View.cpp)

## Goals / Non-Goals

- 在同一帧入口衔接请求编辑、选用计划和提交确认。准备与确认都按 View 定位，已确认状态可追溯到真实渲染。
- 在现有单样本计划及真实消费者上落实切换兼容性。路径相关的 TAA/SSR 准入在本包明确，历史纹理、重投影及累积由对应效果工作包交付。 [历史有效性](../../../../Docs/Architecture.md#temporal-contract) · [D14/D15](../../../../Docs/Developments/D14-D15-ImagePipeline.md#d15-t01)

## Decisions

### View 拥有请求及确认状态

将 `OpaquePath` 并入 `ViewDocumentRequests`，让 `RequestOpaquePath` 和主 View 字段编辑使用同一类型化值域和权威字段。面板从 View 读取请求及确认快照，经 `EditorSession` 提交有 Scene/View 身份的单字段意图。编辑边界合入当前字段集，复用文档冻结、版本、Undo/Redo 和保存快照。重复选中同值是幂等操作。渲染准备和接受结果只更新运行期确认状态。显式离屏 View 走同一渲染合同，其请求生命周期由调用方管理。 [编辑合同](../../../../Docs/Architecture.md#edits) · [场景持久化](../../../../Docs/Architecture.md#asset-persistence)

View 追踪最新路径意图及其非复用身份、待选计划状态和当前 Scene 下最近接受的受光计划身份。准备诊断随当前请求提供，整体帧或其它 View 的错误不能覆盖它。界面在首次匹配帧前显示有效路径尚未确认，等待时仍能显示正在绘制的原策略。材质预览、测试图、实际使用诊断着色的帧只确认自身输出，其路径控件说明适用的受光模式。切换 Scene 时按新身份重新确认，旧颜色的只读引用继续沿原合同管理。 [View 设置](../../../../Docs/Architecture.md#editor-input) · [视口输出](../../../specs/editor-viewport-output/spec.md)

候选资格包括 View/Scene 身份和当前路径请求代。同一请求在连续相机移动时，可以复用仍兼容的编译结果。每帧的 `PreparedView`、绑定资源及派生量仍须对应当前相机、布局、内容和冻结 Shader 代。涉及实际需求集合的变化要重新核对候选键，先前请求的迟到完成或错误可供缓存或诊断，但发布资格已撤销。相同枚举值再次出现也使用这次意图的资格。

### 帧前选择完整计划

在正常帧的准备阶段解析当前两路 View 的实际活跃角色。把仍可能执行的有效策略与候选实际所需的键纳入已有 Shader 准备需求，按帧推进原生额度。资源准入优先保护仍有效的工作和其它已获准消费者。只有选用的策略持有该 View 的本帧图写入和私有资源需求；未选的准备释放自身临时保留，共享上传按实际引用保留。Forward+ 才为实际 Froxel 颜色消费者登记布局与上传。键缺失和瞬时额度分别沿用已有等待原因。Shader 包、反射、编译或设备拒绝保留角色与可定位原因。相关输入或请求更新时可重新准备，继续使用已匹配的缓存成果。 [Shader 准备合同](../../../specs/shader-generation-reload/spec.md) · [Froxel 消费合同](../../../specs/static-forward-rendering/spec.md)

待选方案完整时，帧边界将其封存为该 View 本轮唯一的受光策略。候选仍等待、准备拒绝或被取代时，用原有效策略和**本轮输入**形成正常 View 工作。每个选用结果都遵守同一个帧内 Shader 代和现有图绑定合同，保留物化及执行错误的真实回执。首次尚无有效策略，或原策略也无法满足本轮输入时，沿现有可读旧色和诊断占位规则处理。候选在构图、预检或执行中失败时，按已有恢复和票据协议结束该轮。候选自身的拒绝回执保留在对应请求和失败输入上，后续帧可继续使用原有效策略，等待必要条件变化后再准备候选。 [计划准备](../../../../Docs/Architecture.md#plan-readiness) · [资源准入](../../../../Docs/Architecture.md#graph-resources)

### 以匹配正常提交确认切换

准备允许本轮使用候选。确认入口核对实际选用的策略、候选资格、当前 View/Scene、相机、布局和正常图回执。主视口需要本轮颜色被正常合成采样，离屏 View 需要匹配的输出导出。保活用的部分执行票据、被裁剪的输出和安全 UI 旧图读都没有确认资格。一个 View 的未接受结果不能撤销另一 View 已满足合同的导出。共同的正常图提交失败则无新 View 确认。

同一发布操作更新接受颜色及配套信息、实际路径和历史资格，Runtime 与面板从相同身份读取。有效策略在新请求等待时仍可发布有效帧，路径状态继续指向新请求的真实等待或失败。为此，确认条件同时区分本轮选用的有效策略与匹配待选代的切换候选，保留原有的当前输入校验。图像映射使用真正被接受的准备值。帧统计、Froxel 消费和后到的 GPU 查询按原 View/Scene/票据归属。已成功提交的正常结果可按原合同发布，窗口呈现的独立恢复继续由宿主管理。 [提交与确认](../../../../Docs/Architecture.md#history-commit) · [帧统计](../../../specs/render-frame-statistics/spec.md)

### 从实际生产合同确定历史资格

以 View 最近一次接受的真实场景记录和本轮实际计划为比较边界。基于路径、实际生产 ABI、深度与颜色栅格、格式／样本和输入版本判断受影响的历史资格。路径或栅格不兼容的首个新计划从无对应旧历史的状态开始。候选被拒、被取消或未被接受时，不发布该候选的兼容性变化。原有效计划接受新帧时按该帧的真实输入更新，例如等待切换期间先成功接受 resize 就先结算这次尺寸变化。读取旧画面的资格继续由输出导出和引用决定。 [历史合同](../../../../Docs/Architecture.md#temporal-contract) · [View 输出](../../../specs/editor-viewport-output/spec.md)

| 当前输入变化 | 作用于已接受记录和后续消费 |
| --- | --- |
| 同一 Scene 的位姿连续变化、仅曝光变化 | 保留兼容性，记录真正生产本帧的相机及曝光。分别沿静态深度重投影、曝光重标定合同解释 |
| 路径改变，或生产 ABI、投影、栅格／尺寸、格式／样本不兼容 | 相关历史失去跨此次变化的读取资格。颜色、深度及元数据以同一成功提交为准 |
| Scene 身份或静态内容变化、明确 camera cut | 按既有历史合同失效受影响的记录。Scene 的静态内容版本继续由 Scene 管理 |
| 相同描述下帧槽轮转、瞬态对象变更 | 资源池按真实描述、状态、依赖与完成票据管理存储。历史有效性使用生产合同和语义输入版本 |

通过当前接受记录及使用它的准备、输出与图像映射入口落实这条边界，维持可读旧输出的历史身份。当前 None/FXAA 沿用无时间累积的显示合同。引入真实时域消费者时再分配对应角色的历史纹理和深度；TaaHdr、ReflectionHdr 的生产点和再投影分别遵循架构合同。 [历史有效性](../../../../Docs/Architecture.md#temporal-contract) · [固定 Filament 帧结束参考](../../../../Docs/Reference/Filament/FrameEndAndDraw.md#f14)

### 复用共享资源并按票据退休

切换仅改变不透明子图和实际关联资源。保持 Scene、RenderEngine、编辑状态、共享几何／材质／环境驻留及相同键的 Pipeline。沿描述和实际访问判断图资源复用。最后使用的提交及保留引用均满足原协议后才复用或回收旧存储。切换本身保持有界准备，无场景重载或 `WaitForIdle`。 [路径组装](../../../../Docs/Architecture.md#paths) · [跨帧资源](../../../../Docs/Architecture.md#graph-resources) · [资源池规格](../../../specs/render-graph-resource-pool/spec.md)

## Risks / Trade-offs

- 候选缺项拖慢可画路径或另一 View。准入与 native 预算按实际消费追踪，准备结果与已接受帧分别记账，验证持续出图和资源归属。
- 布局或请求反复变化使旧候选看似匹配。请求身份与动态准备输入分别检查，覆盖往返请求、移动相机和 resize 后的首次确认。
- 有完成票据的失败帧被误作发布凭据，或旧输出仍有读取者时被覆写。继续用现有图回执、导出所有权与提交保活作为实际证据。

## Migration Plan

v1 增加可省略的 `mainView.requested.opaquePath`，取值 `forward` 和 `forward-plus`。当前版本用缺省 Forward 读取已有 v1 场景，也可按缺省值省略字段保存；显式非法值使候选 Open 整体拒绝。现有 v1 解析器拒绝未知字段，带新增字段的文件需要识别该字段的版本。保存只捕获主 View 已接受的请求，恢复时以新文档身份重新准备有效状态。 [文档增量规格](specs/scene-document-persistence/spec.md)
