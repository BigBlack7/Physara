## 2. 验证场景准备、驻留和图池

- [x] 2.1 执行 V1，让各槽先完成初始化与安全复用，再观测连续接受的冻结场景帧。核对零重复静态记录改写、编码、静态上传和无谓创建，同时对照一帧实际深度/颜色 Draw、绑定、上传和创建，解释 View、实例/间接参数及 UI 的真实动态成本。
- [x] 2.2 执行 V2，在同一暖机输入上作一次源槽材质稀疏编辑和一次纯离屏 View 请求变更。核对对受影响记录的逐槽追赶、一次共享提取、两路独立裁剪/设置和接受标样，记录对应版本、写入和提交。
- [x] 2.3 执行 V3，以连续切换和尺寸往返核对当前资源版本、实际上传、物理池命中/创建、可回收容量、预算与在途退休。对场景身份与当前压力各核对一个有判别力的实例，保留真实完成及退出证据。匹配的前置压力用例可直接引用。

## 3. 验证原生同步、统计与 Shader 重载

- [x] 3.1 执行 V4，把真实图中的 Compute 写、图形采样与间接绘制、传输及 staging 读回关联到同一命令链。核对不同域的实际依赖、合法 Map 前的匹配完成、像素、字节及 pitch，并保留一个未完成拒绝的观察。前置原生回放只有覆盖同组合且输入身份匹配时才复用。
- [x] 3.2 执行 V5，对照同输入的统计面板显隐，按来源核对接受场景、图、池、Shader 和 UI 的计数。取一次实际 Pending 到 Ready 的原生观察，确认可用性先于结果读取、时长回到原票据，并说明 Skipped/Unavailable 等实际范围。
- [x] 3.3 执行 V6，在双 View 有旧代在途时以实际 include 保存触发失败并修复。核对请求与源行、原生准备额度、旧代和新代的匹配输出、各自接受票据及真实退休，记录失败期间正常运行和有效修复的证据。

## 4. 测量同画质成本

- [x] 4.1 用同一 Release 源、设置和正式路径建立临时全量准备和逐表面直接索引两个对照。分别在匹配接受输出上核对 HDR、深度、显示线性颜色和有效配置，留存差异、原生读回误差及可复现命令。等画质通过后使用相同输入采样。[对照协议](design.md#benchmark-protocol)

- [x] 4.3 分别判定增量和批处理成本变化。收益结论须有等画质及分布证据，记录退化、波动和适用范围。复杂优化未证实收益时，把复现结果、相关旧 change 与重评项留在本 tasks；必要输入或比较缺失时保持对应验收待完成。
