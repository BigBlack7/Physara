# 独立审查与注释

使用[当前问题单](../../../Docs/CodeReview.md)。维护者调度两个独立项目会话，同一范围串行编辑。同一轮可往返多次，已有未关闭问题时继续本轮。

| 环节 | 责任与交接 |
|---|---|
| A 开发 | 按 spec/design/tasks 实现、写基本注释并完成本地检查。交接基准 commit、相关暂存/未暂存 diff、新增文件、检查入口/结果及限制。待 B 的任务保持未勾选 |
| B 审查与注释 | 独立读合同、实际 diff 与受影响消费者，检查范围内的第一方文件。按[注释标准](../physara-cpp/SKILL.md#annotation)直接补充注释。功能、接口和结构问题记录在问题单，交 A 修改 |
| A 整改 | 按稳定 CR 编号逐项修正并验证，写明证据，只勾选 A 整改项。B 的注释纳入交接版本 |
| B 复核与注释 | 检查实际修正、匹配的回归证据和最终注释，只由 B 勾选复核项。未通过则保留编号、说明原因、撤销对应勾选并交回 A |

不同工作树须核对实际内容，含相关未跟踪文件与必要检查输入。B 只按 spec 影响面审查代码和消费者，按需引用证据，build 树中的生成物不作为代码审查范围。重点按实际变化选择所有权、GPU 寿命、数值语义、失败退出或构建边界。注释不能掩盖未确认的行为，修改注释后检查宏、续行和指令语义。

每项正式发现写位置、违反的合同、可触发的后果、预期修正及验证方法。P0–P3 用于排序，非阻塞建议单列。A 的勾选仅表示已自检。B 可凭源码、合同或复现证据撤回误报并保留理由。没有发现也由 B 写明版本、覆盖、注释和结论，整改注明不适用。必要检查缺失时保持待验收。

B 复核所有正式问题并确认最终版本后，完成原生 verify，再同步、归档。验收后改变代码或构建输入，重新交 B 复核受影响范围。将 CR 编号、修正/复核摘要、注释覆盖、最终版本、证据及限制保存在 change tasks。开发计划仅记状态和 change 引用。归档成功后按[空模板](../../../Docs/CodeReview.md.tpl)重置问题单，未通过或归档失败时保留现场。CLI 的任务计数不能替代 B 验收。

全仓审查同样按实际模块分批记录，覆盖已实现的第一方代码、Shader、CMake、相关检查和文档。第三方核对接入、许可及本地适配。验收留在对应 change tasks，已归档行为的新修正建立新 change。
