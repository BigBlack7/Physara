# C++ 实现与可读性

先读工作包引用的架构合同、公开声明和直接消费者。让函数表达一个抽象层次，让构造成功的对象满足不变量。工厂能失败时明确返回结果。

## 模块和数据

- 按状态所有者、生命周期和消费关系划分模块。组合入口负责装配，算法通过窄接口取得数据。构建关系、公开头和 cpp 内部依赖均遵守同一方向。
- 一项事实只有一个可写来源。转换数据应当改变语义、布局、权限或寿命。已发布快照只读，身份与版本须能识别迟到的结果。序列化使用稳定身份。
- 默认 RAII 与值语义。独占使用 `unique_ptr`，观察关系使用引用、非拥有指针或 `span`。真实共享寿命才引入共享计数。借用的字符串、容器元素、回调或帧内存不能跨越其生存期。
- 声明真实的可空性、单位、线程、阶段及失败结果。异步工作约定单写者、取消、发布和退出。锁内避开未知回调、等待 GPU 和长时间工作。
- 类型优先 Rule of Zero。按真实合同选用 `const`、`noexcept`、`nodiscard` 等。协议/GPU 字段使用固定宽度和明确布局，容器尺寸用 `size_t`。比较和哈希取语义字段，避免把 padding 当数据。

## 防御边界

在接收不可信数据、资源不足、外部库错误或向 GPU/二进制协议提交参数的边界处理可恢复失败。尺寸乘法、对齐、范围和窄化在值可能越界时受检。已由固定上限或上游合同证明安全的内部算术直接使用。异步失效、设备状态变化等会使原证明失效，此时由实际拥有者重新确认。

内部前提优先用类型和断言表达。合法的失败如实传递，在掌握完整上下文处记录一次。禁止用空操作、默认资源或吞异常伪造成功。新重试、状态码、缓存或 fallback 需要真实触发路径、消费者和退出条件。

不得为假想的调用方式或不可达状态添加防御层。数据、线程和寿命未改变时，不在内部逐层重复解析、范围校验、异常捕获或错误包装。新增保护须能指出当前合同下可触发的失败及其处理责任；不能指出时保持直接实现，不预建恢复框架。外部输入和真实资源失败仍按上述边界处理。

## 项目风格

| 对象 | 约定 |
|---|---|
| 文件和布局 | PascalCase，头 `.hpp` 加 `#pragma once`，实现 `.cpp`。4 空格、Allman 大括号、120 列，控制语句有括号体 |
| 标识符 | 类型、函数、常量与枚举项用 PascalCase。局部变量、参数与公开数据字段用 camelCase。成员用 `m_PascalCase`，静态成员用 `s_PascalCase`，宏用项目统一前缀和 UPPER_SNAKE |
| 命名空间 | 各段 PascalCase，沿用 RHI/RT 等统一拼写。头中不写 `using namespace`。外部协议保留原拼写 |
| 实现作用域 | 第一方默认不用匿名命名空间。cpp 私有函数/对象在所属领域用 `static` 或放入实际拥有者的 private 成员。跨文件内部域需要真实消费者 |
| 包含顺序 | 自身头、标准库、第三方、项目头。组间空行，直接包含所用声明 |

第三方 override、ADL 钩子或其他固定协议名称属于命名例外，须在声明旁注明协议来源、必须保留的拼写和原因，不能只依靠维护者自行推断。

选用接口、模板、Pimpl 或 helper 时，说得清它减少了哪项实际复杂度。函数约 80 行、实现文件约 600 行或公开头约 300 行时检查职责，这些数字用于提醒阅读，不要求机械拆分。只格式化触及的第一方范围，移植代码保留来源与许可。

## 注释

让熟悉 C++ 但不熟悉本模块的维护者, 能从注释说明文件负责什么、接口如何使用、流程如何推进以及失败后处于什么状态. 第一方说明文字使用中文与英文标点. 声明文档统一使用紧凑的 Doxygen `///`, 实现中的阶段和原因使用 `//`, 必要的字段说明使用 `///<`.

### 按理解难度选择深度

| 代码情况 | 注释深度 | 应说明的内容 |
|---|---|---|
| 默认构造、简单访问器、直接转发 | 可省略或同组共用说明 | 名称和类型未表达的额外语义 |
| 普通函数、内部辅助函数 | 通常 1–2 行 | 用途、转换或处理的实际语义 |
| 有调用约束的接口、重要数据类型 | 通常 3–8 行 | 输入约束、结果、状态变化及相关的所有权、寿命、线程和失败行为 |
| 多阶段算法、状态机、同步及发布流程 | 入口概述加关键位置的局部说明 | 阶段、关键不变量、执行顺序的原因及失败后留下的状态 |

行数只提示篇幅, 按理解所需的背景和约束选择深度. 短小的资源退休或跨线程发布也可能需要完整合同. 每个非平凡函数都有用途说明, 包括 cpp 内部函数; 不逐句翻译循环、赋值或类型已经清楚表达的内容.

### 阅读入口与文档位置

- 文件入口通常用 2–4 行说明职责、主要输入输出和边界. 头文件说明公开合同, 实现文件说明实现组织, 避免复制同一段文字.
- 类型说明表达领域含义、重要字段关系和有效状态. 字段只补充有歧义的单位、范围、哨兵值、坐标空间或身份语义; 同组字段可共用说明.
- 调用者需要的合同写在声明旁, 实现步骤与设计原因写在定义或关键分支旁. 同一合同只维护一份; 同组访问器或固定协议转发可共用说明.
- 复杂实现先概述数据如何经过各阶段, 再在关键转换处解释顺序、近似、精度、不变量和失败恢复. 说明必须对应当前实现, 不用注释承诺尚未实现的能力.
- 现代 C++ 重点补充类型未充分表达的借用有效期、容器失效、回调时机、异步资源退休、成功/失败后的修改范围. `noexcept` 或返回 `Result` 本身不等于失败无副作用.

### Doxygen 的最小使用

`@brief` 简述用途. `@param` 只解释有特殊含义或约束的参数; `@return` 说明特殊成功值、失败形式与结果所有权. 实际存在调用前提、状态保证或类型不变量时使用 `@pre`、`@post`、`@invariant`. 线程与寿命可用 `@note` 或 `@par 线程与寿命`; 真正抛异常或存在模板语义要求时使用 `@throws`、`@tparam`. 不为每个声明填满标签, 不添加作者、日期、空标签或装饰边框.

```cpp
/// @brief 通过同目录临时文件原子发布 Shader 包.
/// @return true 表示内容改变, false 表示与旧文件相同; 失败返回 Failure.
/// @note 发布失败时保留旧包. 输入仅在调用期间借用.
[[nodiscard]] Result<bool> WritePackage(const std::filesystem::path &path, const ShaderPackage &package) noexcept;
```

Shader 说明数学模型和精度, CMake 用 `#` 说明 target、依赖和非平凡生成步骤. 上游原样代码保留原注释和许可, 在项目适配处补充中文说明.

A 实现时写基本说明, B 按[独立审查闭环](../physara-review/SKILL.md)通读并补齐本轮涉及的完整第一方文件. A 修改后由 B 同步复核注释. 删去失效注释和注释掉的旧实现, TODO 给出可追踪事项与退出条件. 注释质量按阅读入口、合同准确性和流程可理解性验收, 不按注释行数或比例验收.
