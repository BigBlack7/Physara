# C++ 实现与可读性

先读工作包引用的架构合同、公开声明和直接消费者。让函数表达一个抽象层次，让构造成功的对象满足不变量。工厂能失败时明确返回结果。

## 模块和数据

- 按状态所有者、生命周期和消费关系划分模块。组合入口负责装配，算法通过窄接口取得数据。构建关系、公开头和 cpp 内部依赖均遵守同一方向。
- 一项事实只有一个可写来源。转换数据应当改变语义、布局、权限或寿命。已发布快照只读，身份与版本须能识别迟到的结果。序列化使用稳定身份。
- 默认 RAII 与值语义。独占使用 `unique_ptr`，观察关系使用引用、非拥有指针或 `span`。真实共享寿命才引入共享计数。借用的字符串、容器元素、回调或帧内存不能跨越其生存期。
- 声明真实的可空性、单位、线程、阶段及失败结果。异步工作约定单写者、取消、发布和退出。锁内避开未知回调、等待 GPU 和长时间工作。
- 类型优先 Rule of Zero。按真实合同选用 `const`、`noexcept`、`nodiscard` 等。协议/GPU 字段使用固定宽度和明确布局，容器尺寸用 `size_t`。比较和哈希取语义字段，避免把 padding 当数据。

## 防御边界

在接收不可信数据、资源不足、外部库错误或向 GPU/二进制协议提交参数的边界处理可恢复失败。尺寸乘法、对齐、范围和窄化在值可能越界时受检。已由固定上限或上游合同证明安全的内部算术直接使用。异步失效、设备状态变化等会使原证明失效，此时由实际拥有者重新确认。

内部前提优先用类型和断言表达。合法的失败如实传递，在掌握完整上下文处记录一次。禁止用空操作、默认资源或吞异常伪造成功。新重试、状态码、缓存或 fallback 需要真实触发路径、消费者和退出条件。

不得为假想的调用方式或不可达状态添加防御层。数据、线程和寿命未改变时，不在内部逐层重复解析、范围校验、异常捕获或错误包装。新增保护须能指出当前合同下可触发的失败及其处理责任；不能指出时保持直接实现，不预建恢复框架。外部输入和真实资源失败仍按上述边界处理。

## 项目风格

| 对象 | 约定 |
|---|---|
| 文件和布局 | PascalCase，头 `.hpp` 加 `#pragma once`，实现 `.cpp`。4 空格、Allman 大括号、120 列，控制语句有括号体 |
| 标识符 | 类型、函数、常量与枚举项用 PascalCase。局部变量、参数与公开数据字段用 camelCase。成员用 `m_PascalCase`，静态成员用 `s_PascalCase`，宏用项目统一前缀和 UPPER_SNAKE |
| 命名空间 | 各段 PascalCase，沿用 RHI/RT 等统一拼写。头中不写 `using namespace`。外部协议保留原拼写 |
| 实现作用域 | 第一方默认不用匿名命名空间。cpp 私有函数/对象在所属领域用 `static` 或放入实际拥有者的 private 成员。跨文件内部域需要真实消费者 |
| 包含顺序 | 自身头、标准库、第三方、项目头。组间空行，直接包含所用声明 |

第三方 override、ADL 钩子或其他固定协议名称属于命名例外，须在声明旁注明协议来源、必须保留的拼写和原因，不能只依靠维护者自行推断。

选用接口、模板、Pimpl 或 helper 时，说得清它减少了哪项实际复杂度。函数约 80 行、实现文件约 600 行或公开头约 300 行时检查职责，这些数字用于提醒阅读，不要求机械拆分。只格式化触及的第一方范围，移植代码保留来源与许可。

## 注释

让维护者先从注释读懂文件/类型的职责、用途和数据流，再深入代码。公开声明就近解释实际涉及的单位、所有权、线程和寿命。简单操作通常一两句，同组访问器可共享说明。复杂算法在入口交代输入、输出与步骤，在关键分支旁解释顺序、近似、不变量及失败恢复。Shader 说明数学模型和精度，CMake 说明 target 和依赖。第一方说明文字使用中文与英文标点。

A 实现时写基本说明，B 在审查和复核时直接完善。删去失效注释和注释掉的旧实现，TODO 给出可追踪事项与退出条件。上游原样代码保留原注释，在项目适配处解释差异。
