# 与风险相称的验证

在现有 change tasks 中写清被改变的可观察结果、可能失效的边界和最小有效检查。可合并验证同一合同的任务。等级帮助选证据，无需为每个函数填表、安排一套测试或另写报告。已采纳的 spec、工作包验收与明确指定的检查仍须满足。

| 影响 | 从哪里取得证据 |
|---|---|
| L0 注释、文档、纯排版 | 核对内容、diff、链接或配置解析。涉及宏续行、指令或生成输入才检查相应编译语义。通常新增测试为零 |
| L1 内部实现、局部重构、纯算法 | 运行直接受影响的既有检查。行为有变化且缺少覆盖，才补能区分正确与错误结果的代表性用例 |
| L2 公共接口、资产格式、跨模块合同或 ABI | 核对直接消费者、布局/反射、真实可达的拒绝或兼容路径。Shader 编译接口可由编译、反射和独立消费者证明 |
| L3 同步、GPU 在途寿命、线程/context 或实际设备语义 | 验证改变的提交、完成、退出或读回路径。GPU/驱动相关结论需要真实 backend，纯 CPU 并发用能触发相应时序的检查 |

按后果和证据能否区分错误结果选深度。同一 change 可分别验证 CPU 合同和原生合同。错误分支、取消、规模场景只在变更确实引入或触及这种风险时纳入。结构校验只证明结构正确。

## 开发测试的存放

开发时编写的测试代码、脚本、Shader/JSON 样例、故障注入和临时 CMake 工程，只能放在 `build/` 下按工作包归类的目录，禁止写入正式模块、Shaders 或其他交付源码目录，也不纳入版本控制。正式代码不保留测试专用宏、入口或故障开关，正式 CMake 不注册这些测试目标或默认样例包。

build 是可整目录删除的临时空间。正式工程必须能从仓库输入重新配置/构建，不依赖保留的测试文件，不自动恢复被清理的测试。复现所需的本地输入由交接另行提供；实际命令、结果和未覆盖范围保存在 change tasks，不能把本地测试路径当成永久存在的工程入口。

## 测试预算与停止条件

1. 先查已有编译检查、断言、消费者或用例。新增用例前指出它能发现哪项尚未覆盖的回归，并给出独立于被测实现的预期。复用覆盖同一风险的结果。
2. 每个尚未覆盖的独立风险先选一个代表性检查。有必要时验证最后一个合法索引及紧邻非法值，不逐字段、逐分支或穷举参数组合。同一任务拟新增十余个用例时，先缩减为不同缺陷所需的最小集合。避免镜像公式、私有实现快照、平凡 getter、标准库/第三方自身正确性和为覆盖率重复断言；故障注入仅用于本次改变的真实失败合同，不扩展为分配点或极限输入的全量扫描。
3. 从最小受影响目标开始。公共合同或共享构建输入变化时扩大到真实消费者，完整矩阵只在阶段验收、明确要求或有影响全局的证据时运行。同一输入、环境和检查已有匹配结果即可引用，说明哪些检查是复用的。
4. 已满足本次验收、已识别风险各有证据、未覆盖范围已说明，即停止。只在失败、输入变化或发现具体缺口时追加检查。必要环境缺失则记录待验证的合同，保留相关验收项。交付写实际运行、结果与限制。

测试规模和重复运行必须考虑开发耗时与 Token 成本。禁止以“更保险”为由增加无独立价值的边界用例、重复完整矩阵或新建测试基础设施；一次检查已证明的合同不在每个任务末尾再证明。已有 spec 若要求明显超出实际风险的检查，先按维护者授权调整规划，不默默漏掉验收。

## 性能

只有提出性能或内存结论时才做相应测量。固定版本、设备/驱动、输入、分辨率、画质、VSync、预热和采样，分别报告 CPU、GPU、等待及适当分布。缓存/池有容量、失效、淘汰和退出条件。优化围绕测出的分配、上传、状态切换或阻塞进行，比较时保持同等画质。
